Light and Dark Mode

Materia has a light mode and a dark mode. Visitors pick one from the sun and moon menu in the nav bar, which offers three choices:

Choice What it does
Light Always light
Dark Always dark
System Follows the operating system, and switches when the system switches

System is the default. The browser remembers the visitor’s choice in localStorage under the key color-mode. Choosing System removes the key.

How it works

The .dark class on the <html> element turns dark mode on. Every theme token has a dark value under .dark in src/styles/themes.css, so adding or removing that one class recolors the whole app. React does not re-render any component. Theme Tokens lists the values.

Three pieces work together:

1. A script in index.html sets the class before the page first paints, so a dark-mode visitor never sees a flash of light colors:

<script>
	// Applies the saved colour mode before first paint, so a dark-mode
	// visitor never sees a flash of the light theme.
	(function () {
		var mode = localStorage.getItem("color-mode");
		var dark = mode === "dark" || (mode !== "light" && matchMedia("(prefers-color-scheme: dark)").matches);
		document.documentElement.classList.add(dark ? "dark" : "light");
	})();
</script>

2. ThemeProvider in src/providers/theme-provider.tsx holds the current choice, saves it, swaps the class, and listens for the system to change while the choice is System. src/main.tsx wraps the whole app in it.

3. The useTheme hook gives any component the current mode and a way to change it.

useTheme

import { useTheme } from "@/providers/theme-provider";

const { theme, resolvedTheme, setTheme } = useTheme();
Value Type Meaning
theme "light" | "dark" | "system" What the visitor picked
resolvedTheme "light" | "dark" What is on screen now. With System, this is the system’s mode
setTheme (theme) => void Changes the choice and saves it

The nav bar builds its menu from these values:

<DropdownMenuRadioGroup value={theme} onValueChange={(value) => setTheme(value as Theme)}>
	<DropdownMenuRadioItem value="light">
		<Sun />
		Light
	</DropdownMenuRadioItem>
	<DropdownMenuRadioItem value="dark">
		<Moon />
		Dark
	</DropdownMenuRadioItem>
	<DropdownMenuRadioItem value="system">
		<Monitor />
		System
	</DropdownMenuRadioItem>
</DropdownMenuRadioGroup>

Use resolvedTheme when a component needs to know what is on screen. Use theme to show what the visitor chose.

Styling for dark mode

Most of the time you write nothing extra. Use theme tokens such as bg-card, text-foreground and border-border, and dark mode follows.

When an element needs a different color in dark mode, add a dark: variant:

<span className="text-white dark:text-black">A</span>

dark: matches anything inside <html class="dark">. src/styles/index.css sets this up:

@custom-variant dark (&:is(.dark *));

Use a token where one already covers the case, and dark: for the rest. Colors shows where the template uses dark:.

Charts

Charts draw on a canvas, and a canvas cannot follow a CSS class. useChartTheme() reads the grid, tick and tooltip colors again whenever resolvedTheme changes, and the charts redraw with the new colors. Chart Colors explains this.

Changing the default

Start in dark mode for visitors who have not chosen yet. Change the script in index.html so a missing choice counts as dark:

var dark = mode !== "light";

Then change readTheme in src/providers/theme-provider.tsx to return "dark" when nothing is saved:

function readTheme(): Theme {
	const saved = localStorage.getItem(STORAGE_KEY);
	return saved === "light" || saved === "dark" ? saved : "dark";
}

Offer light mode only. Make three changes:

  1. Remove the mode menu from src/components/layout/nav-bar/nav-bar.tsx.
  2. Change the script in index.html to add light every time:
document.documentElement.classList.add("light");
  1. Change readTheme in src/providers/theme-provider.tsx to return "light", so the provider stops following the system:
function readTheme(): Theme {
	return "light";
}

The dark values in themes.css then go unused. You can leave them in place for later.
