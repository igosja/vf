Layout Overview

Most pages sit inside the same frame, AppShell, from src/components/layout/app-shell.tsx. It has four parts:

Part On wide screens (1280px and up) On smaller screens
Sidebar An icon rail down the left edge. Pointing at a section opens its links in a flyout panel Hidden. A button opens the same links in a drawer
Content header A bar at the top of the page with the title and the page’s actions The same
Page Scrolls between the sidebar and the nav bar Fills the width
Nav bar A column of round buttons down the right edge On phones, a bar across the bottom of the screen

AppShell also holds the toast area and the loading screen between pages, and it provides the tooltip and sidebar state to every page.

The frame in code

export function AppShell() {
	usePageLoader();

	const { pathname } = useLocation();
	const viewport = useRef<HTMLDivElement>(null);
	useEffect(() => {
		viewport.current?.scrollTo(0, 0);
	}, [pathname]);

	return (
		<TooltipProvider>
			<SidebarProvider>
				<Sidebar />
				<ScrollArea viewportRef={viewport} className="h-screen print:h-auto" scrollbarClassName="z-9 print:hidden">
					<main className="px-4 pb-14 sm:pe-17 sm:pb-0 xl:pl-28.5 xl:has-data-[slot=secondary-sidebar]:pl-24 print:p-0">
						<Outlet />
					</main>
				</ScrollArea>
				<NavBar />
				<RouteLoader />
				<Toaster />
			</SidebarProvider>
		</TooltipProvider>
	);
}
  • The page renders where <Outlet /> sits.
  • The page scrolls inside ScrollArea, not in the browser window. This keeps the scrollbar under the nav bar, and dialogs and drawers cover it. When the address changes, the effect scrolls back to the top.
  • The padding on <main> leaves room for the nav bar: at the bottom on phones (pb-14), on the right from 640px (sm:pe-17), and for the sidebar rail from 1280px (xl:pl-28.5).

The standalone frame

Login, Register, Forgot Password, Coming Soon and Error use BlankShell instead. It has no sidebar and no nav bar, so each page fills the window and draws its own background. Pages and Routes shows how the routes choose a frame.

Page widths

Each page sets its own width inside the frame:

Kind of page Wrapper Width
Dashboards and most pages mx-auto w-full max-w-400 pb-4 Up to 1600px, centered
UI element pages mx-auto flex max-w-4xl flex-col gap-4 pb-4 Up to 896px, for easy reading
Content, form, Charts, Maps and Billing pages mx-auto flex max-w-300 flex-col gap-4 pb-4 Up to 1200px
App pages flex items-start with a secondary sidebar The full width

A dashboard page starts like this:

export default function Saas() {
	return (
		<div className="mx-auto w-full max-w-400 pb-4">
			<ContentHeader title="SaaS Dashboard">{/* actions */}</ContentHeader>

			<Overview />

			<div className="grid grid-cols-1 gap-4 xl:grid-cols-3">
				<div className="flex min-w-0 flex-col gap-4 xl:col-span-2">
					<MrrMovement />
					<ProductEngagement />
				</div>

				<div className="flex min-w-0 flex-col gap-4">
					<PlanMix />
					<TrialFunnel />
				</div>
			</div>
		</div>
	);
}

min-w-0 on each column lets a chart inside it shrink with the window. Without it, a wide chart can push the column out of the grid.

App pages

The app pages (Mail, Contacts, File Manager, Todo Lists and the others) have a second sidebar of their own, with folders, filters or groups. It sits beside the content on wide screens and opens as a drawer on smaller ones:

return (
	<div className="flex items-start">
		<TodoSidebar />

		<div className="min-w-0 flex-1 pb-4">
			<ContentHeader>
				<SearchField className="w-full max-w-140" placeholder="Search Todo..." aria-label="Search todo" shortcut />
			</ContentHeader>

			<Card className="p-0">{/* the list */}</Card>
		</div>
	</div>
);

Loading screens

Two loading screens show the logo with a spinning ring.

The first load. index.html holds a loading screen in plain HTML and CSS, so it shows before any JavaScript runs. usePageLoader(), called once by each frame, fades it out after the browser has loaded everything, fonts and images included. The first page never appears half drawn.

Between pages. Each page downloads on its own when someone opens it. RouteLoader shows the same loading screen while a page downloads, after a 150-millisecond wait, so a page that is already cached never flashes it.

Printing

Printing a page leaves out the sidebar, the nav bar, the content header and the scroll area. The page prints at full width. The Invoice and Billing pages print as clean documents this way.

Elements with print:hidden stay off the paper. Add the class to anything else that should not print:

<div className="print:hidden">Only on screen</div>
