Code Style and Tooling

The template comes with Prettier for formatting and TypeScript in strict mode for type checking. Both run from npm run scripts, so they work the same in every editor.

Formatting with Prettier

Format every file in src/:

npm run format

The rules live in .prettierrc:

{
	"trailingComma": "es5",
	"tabWidth": 4,
	"useTabs": true,
	"singleQuote": false,
	"printWidth": 160,
	"bracketSpacing": true,
	"plugins": ["prettier-plugin-tailwindcss"],
	"tailwindStylesheet": "./src/styles/index.css",
	"tailwindFunctions": ["cn", "cva"]
}
  • The template indents with tabs and uses double quotes.
  • Lines wrap at 160 characters, so a component’s class list stays on one line in most cases.
  • prettier-plugin-tailwindcss sorts Tailwind classes into one fixed order. It reads src/styles/index.css to learn the template’s own utilities, and it sorts the classes inside cn() and cva() calls as well as in className.

.prettierignore skips src/components/charts/maps/, the map shapes that ship as they come from jsvectormap.

Type checking

Check the types without building:

npm run typecheck

tsconfig.json turns on strict mode and a few extra checks. The ones you will notice most:

Setting What it catches
strict Values that might be null or undefined, missing types and loose function types
noUnusedLocals, noUnusedParameters Imports, variables and parameters you no longer use
noFallthroughCasesInSwitch A case that runs on into the next one
verbatimModuleSyntax A type imported without the type keyword

The last one means you import a type like this:

import type { ComponentProps } from "react";
import { useState, type ReactNode } from "react";

npm run build runs the same check first and stops on the first error, so keep npm run typecheck clean while you work.

Editor setup

In Visual Studio Code, install two extensions:

  • Prettier, to format on save with the project’s rules
  • Tailwind CSS IntelliSense, for class name completion and color previews

Then add these settings to .vscode/settings.json in the app folder:

{
	"editor.defaultFormatter": "esbenp.prettier-vscode",
	"editor.formatOnSave": true,
	"tailwindCSS.experimental.configFile": "src/styles/index.css",
	"tailwindCSS.classFunctions": ["cn", "cva"]
}

configFile tells IntelliSense where the Tailwind setup lives, because Tailwind CSS 4 keeps it in CSS and not in a tailwind.config.js file. classFunctions turns on completion inside cn() and cva().

Other editors have Prettier and Tailwind plugins too. Point them at the same .prettierrc and src/styles/index.css.

Linting

The template does not include ESLint. TypeScript’s strict checks catch most mistakes, and Prettier handles formatting. To add ESLint, follow the Vite React template’s setup, which uses typescript-eslint and the React Hooks rules.

Conventions in the code

You will find these patterns across the template. Following them keeps new code consistent with the rest:

  • Use the components as they are. Import Button, Card or Dialog from src/components/ui and compose them on the page. Write a new component only when you use the same piece in several places.
  • Write cards out in full. Four stat cards written four times read better than a loop over four settings objects. Use a loop when the items come from a data file or the list is long.
  • Keep one card per file on dashboards, named after the card: budget-expenses.tsx exports BudgetExpenses.
  • Join class names with cn() when a class depends on a value. It also lets a className passed by the parent override the component’s own classes:
<div className={cn("flex items-center gap-1 text-sm", positive ? "text-emerald-500" : "text-red-400", className)} />
  • Size an icon only when it needs a size other than the default. Every Lucide icon starts at size-4.5, set once in src/styles/base.css. Icons explains this.
  • Comment the reason, not the code. The template’s comments explain why a line is there. A comment that repeats what the line does gets in the way.
