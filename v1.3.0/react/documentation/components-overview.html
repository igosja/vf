Components Overview

The building blocks of every page live in src/components/ui. They are shadcn/ui components: React components built on Radix UI for behavior and accessibility, and styled with Tailwind classes. Materia restyled each one in place to match its design, so you import them and use them as they are.

import { Button } from "@/components/ui/button";
import { Card, CardHeader, CardTitle } from "@/components/ui/card";

The code is yours. Each component is a file in your project, not a package, so you can open it and change it.

The Materia look

The restyling follows a few rules that run through every component:

  • Rounded shapes. Buttons, badges and inputs in pill shapes, cards at rounded-2xl, and the four-lobed avatar-mask on avatars, icon tiles and icon buttons.
  • Flat surfaces. Cards have no border and no shadow. The light blue page background sets them apart. Only popups and floating panels carry a shadow.
  • Tints instead of fills. Badges, alerts and active menu items use a color at low opacity behind text in the same color, such as bg-primary/10 text-primary.
  • Theme tokens throughout. Every component reads bg-card, text-foreground, border-input and the other tokens, so all of them work in light and dark mode.

Variants and sizes

Components with styles to choose from take variant and size props. The options live in a cva() call at the top of the file:

const buttonVariants = cva("inline-flex shrink-0 items-center justify-center gap-2 rounded-full border text-sm ...", {
	variants: {
		variant: {
			default: "border-primary bg-primary text-primary-foreground hover:brightness-110",
			outline: "border-input text-foreground hover:bg-accent active:bg-accent dark:border-input",
			// ...
		},
		size: {
			default: "h-10 px-5",
			sm: "h-8 gap-1.5 px-3.5",
			// ...
		},
	},
	defaultVariants: {
		variant: "default",
		size: "default",
	},
});

To add a variant, add a key with its classes. TypeScript picks it up, so <Button variant="your-key"> works right away with completion in your editor.

className and asChild

Every component accepts className, and your classes win over the component’s own through cn():

<Button className="w-full">Sign in</Button>

Many components accept asChild. With it, the component passes its styles and behavior to its single child instead of rendering its own element. Use it to make a button that is a link:

<Button asChild>
	<Link to="/apps/mail">Open the inbox</Link>
</Button>

data-slot

Each component sets a data-slot attribute on its root, such as data-slot="card" or data-slot="card-title". Other components and parent styles use it to find their parts. The Navigate menu in the content header finds each card’s title this way, and a parent can style a child component with a class such as [&_[data-slot=card-title]]:text-lg.

Adding more shadcn/ui components

The shadcn command line tool adds components that the template does not include:

npx shadcn@latest add hover-card

components.json points the tool at the right folders and at src/styles/index.css. A new component uses the theme tokens, so it picks up the Materia colors. Its shapes and spacing follow the default shadcn style, so compare it with the components next to it and adjust its classes if it looks out of place.

Do not run add for a component that already exists in src/components/ui. The tool would replace the restyled file with the plain shadcn version. To see what the template changed, compare a file with the same component in the shadcn/ui docs.
