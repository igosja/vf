Rich Text Editor

RichTextEditor from src/components/common/rich-text-editor.tsx is a text editor with bold, italic, underline, numbered and bulleted lists, links and images. It runs on Quill 2, with a toolbar of Lucide icons in place of Quill’s own. The Messages app uses it for replies, and the Rich Text Editor page at /components/rich-text-editor shows it on its own.

Type in the preview and try the toolbar.

Using it

import { RichTextEditor } from "@/components/common/rich-text-editor";

<RichTextEditor className="rounded-sm border border-input" placeholder="Write something..." />
Prop What it does
placeholder The gray text shown while the editor is empty
className Classes for the outer wrapper. The editor has no border of its own, so each page gives it the frame it needs

The Messages app gives it a different frame: a tinted background that switches to the card color while you type:

<RichTextEditor className="rounded-xl border-2 border-transparent bg-muted transition-colors focus-within:border-border focus-within:bg-card" />

Reading the editor’s content

The component shows the editor but does not pass its content anywhere yet. To use the text, add an onChange prop that hands it up. In rich-text-editor.tsx, accept the prop:

export function RichTextEditor({
	placeholder,
	className,
	onChange,
}: {
	placeholder?: string;
	className?: string;
	onChange?: (html: string) => void;
}) {

Then listen for changes right after Quill starts, inside the useEffect:

quillRef.current = new Quill(editorRef.current, {
	modules: { toolbar: toolbarRef.current },
	placeholder,
	theme: "snow",
});

quillRef.current.on("text-change", () => {
	onChange?.(quillRef.current!.getSemanticHTML());
});

Now the page receives the content as HTML each time it changes:

const [body, setBody] = useState("");

<RichTextEditor onChange={setBody} />

getSemanticHTML() returns clean HTML for saving or sending. To keep the content in Quill’s own format, which keeps every detail of the formatting, use getContents() instead. The Quill API docs cover both.

If you show the saved HTML on a page later, pass it through a sanitizer such as DOMPurify before rendering it with dangerouslySetInnerHTML. Text from an editor can contain markup that a visitor typed.

Changing the toolbar

The toolbar is plain HTML inside the component. Each button’s class names the Quill format it applies: ql-bold, ql-italic, ql-list with value="ordered", and so on. To add a format, add a button with its class and an icon:

<button type="button" className="ql-strike" aria-label="Strikethrough">
	<Strikethrough />
</button>

Then remove Quill’s own icon for that format, so it leaves yours in place. Add the format’s name to the list in the useEffect:

for (const name of ["bold", "italic", "underline", "list", "link", "image", "strike"]) delete icons[name];

The Quill formats page lists every format and its class.

Styling

src/styles/quill.css imports Quill’s Snow theme and restyles it to match the template: the toolbar buttons, the editor text and the link tooltip. The component imports this file itself, so the styles only load on pages that use the editor.

Why it mounts in an effect

Quill takes over the element it is given, so the component creates the editor in a useEffect, once the element exists. The quillRef.current check stops it from creating a second editor when React runs the effect twice in development mode.
