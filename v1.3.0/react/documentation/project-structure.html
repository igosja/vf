Project Structure

The app folder holds a standard Vite project. You write everything in src/, and Vite copies public/ into the build without changing it.

app/
├── index.html            The one HTML page: fonts, the first-paint script, the page loader
├── public/
│   └── img/              Photos, flags, browser logos, favicons
├── src/
│   ├── main.tsx          Starts React, the theme provider and the router
│   ├── routes.tsx        Every page and its address
│   ├── components/
│   │   ├── ui/           shadcn/ui components, restyled
│   │   ├── layout/       The frame around every page: sidebar, nav bar, content header
│   │   ├── common/       Components the template shares across pages
│   │   └── charts/       Chart colors, the chart legend and the map component
│   ├── data/             The demo data each page shows, one file per subject
│   ├── lib/              Small helpers: cn() and formatSize()
│   ├── pages/            One folder per page
│   ├── providers/        Light and dark mode, and the sidebar drawers
│   ├── styles/           The stylesheets
│   └── types/            Type declarations for packages that ship without them
├── components.json       Settings for the shadcn/ui command line tool
├── vercel.json           Sends every address to index.html on Vercel
├── vite.config.ts        Vite plugins and the @ import alias
├── tsconfig.json         TypeScript settings
├── .prettierrc           Formatting rules
└── package.json          Packages and scripts

src/pages

Each page has its own folder, and the folder path matches the page’s address. src/pages/dashboards/crm/page.tsx is the page at /dashboards/crm.

pages/
├── dashboards/           e-commerce, analytics, project-management, crm, email-marketing, saas
├── apps/                 file-manager, contacts, mail, messages, ai-agent, photos, todo-lists, calendar
├── user/                 profile, timeline, photos, connections, preferences
├── pages/                invoice, pricing-tables, billing, search-results, faq, teams,
│                         login, register, forgot-password, coming-soon, error
├── content/              typography, figures, images, tables, icons
├── components/           one folder per UI element, plus charts and maps
├── forms/                elements, input-groups, layouts, templates, validation
└── not-found.tsx         Shown for any address that has no page

page.tsx is the page itself, and it exports the page as its default export. A page that grows long splits into more files in the same folder:

  • Dashboards keep one file per card. src/pages/dashboards/saas/plan-mix.tsx holds the Plan Mix card, and overview.tsx holds the row of stat cards at the top. page.tsx places the cards in a grid.
  • Apps split out their sidebar, dialogs and panels. The Mail app has page.tsx, sidebar.tsx and thread.tsx.
  • The User pages share their cover, header and about card. These live one level up, in src/pages/user/.

src/components

ui/ holds the shadcn/ui components: Button, Card, Dialog, Select and the rest. The template restyles them in place, so you import and use them as they are. Components Overview lists them all.

layout/ holds the frame around the pages:

File What it is
app-shell.tsx The frame for most pages: sidebar, nav bar, scroll area, toasts
blank-shell.tsx The frame for pages that stand alone: Login, Register, Forgot Password, Coming Soon, Error
sidebar/ The icon rail with its flyout menu, the drawer on small screens, and the secondary sidebar some apps use
nav-bar/ The bar on the right with search, notifications, messages, tasks, color mode and the user menu
content-header.tsx The bar at the top of each page with its title, breadcrumb and actions
route-loader.tsx The loading screen between pages

common/ holds components the template uses on many pages, such as IconButton, Avatar, SearchField, DateRangePicker and Trend. Template Components covers each one.

charts/ holds the chart colors, the chart legend and the VectorMap component, plus the extra map shapes in charts/maps/.

src/data

Every list, table and chart in the template reads its numbers and text from a file in src/data/. The file names follow the subject: crm.ts, mail.ts, navigation.ts. Each file exports typed constants:

export type Plan = {
	plan: string;
	price: number;
	subscribers: number;
	color: string;
};

export const PLAN_MIX: Plan[] = [
	{ plan: "Starter", price: 12, subscribers: 1420, color: "text-cyan-500" },
	{ plan: "Pro", price: 29, subscribers: 1126, color: "text-sky-500" },
	{ plan: "Business", price: 39, subscribers: 548, color: "text-purple-400" },
	{ plan: "Enterprise", price: 85, subscribers: 154, color: "text-amber-500" },
];

Pages import these constants. To show your own data, change the values in the file, or fetch from your server and pass the result in the same shape. Working with Data explains both.

src/data/navigation.ts is special: it holds the sidebar menu. Sidebar Menu explains how to edit it.

src/styles

File What it holds
index.css The entry point. Imports Tailwind and the other files, and sets the font, the primary color and the custom animations
themes.css The theme colors for light and dark mode
base.css Page defaults: body text, headings, links and the default icon size
utilities.css The two custom utilities, avatar-mask and no-scrollbar
fullcalendar.css Calendar styles, scoped to the .calendar wrapper
quill.css Text editor styles, loaded by the RichTextEditor component
jsvectormap.css Map styles, loaded by the VectorMap component

The @ alias

vite.config.ts and tsconfig.json both point @ at src/, so an import reads the same from any folder:

import { Button } from "@/components/ui/button";
import { PLAN_MIX } from "@/data/saas";

Files inside the same page folder import each other with a relative path instead, such as import { PlanMix } from "./plan-mix";.

Naming

  • File names use kebab case: date-range-picker.tsx, recent-orders.tsx.
  • Components use Pascal case: DateRangePicker, RecentOrders.
  • A page file exports its page as the default export. Every other component file uses named exports.
  • Data constants use upper case: RECENT_ORDERS, NAVIGATION.
