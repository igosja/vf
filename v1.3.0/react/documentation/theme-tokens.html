Theme Tokens

Theme tokens are the colors with a role in their name: background, card, foreground, border and so on. Each token holds one value in light mode and another in dark mode. A component built from tokens works in both modes without any extra classes.

Switch the preview between Light and Dark to see every token change.

Where tokens live

Tokens take two steps to become Tailwind classes.

1. src/styles/themes.css sets the values. Light values sit on :root, and dark values sit under the .dark class:

:root {
	--background: #edf4fb;
	--foreground: #275881;
	--card: #ffffff;
	/* ... */
}

.dark {
	--background: #1c282f;
	--foreground: #84b0d3;
	--card: #1e2f39;
	/* ... */
}

2. src/styles/index.css turns them into Tailwind colors. The @theme inline block maps each variable to a Tailwind color name:

@theme inline {
	--color-background: var(--background);
	--color-foreground: var(--foreground);
	--color-card: var(--card);
	/* ... */
}

Tailwind now has bg-background, text-foreground, bg-card, border-border and every other utility for each token. inline makes each class point at the variable instead of copying its value, so when the .dark class switches the variables, every class follows at once.

The names follow shadcn/ui, so a component you add with the shadcn command line tool picks up the Materia colors with no changes.

Text has three levels, one more than shadcn/ui. foreground is the normal body text, emphasis-foreground stands out from it, and muted-foreground steps back. card-foreground, popover-foreground and secondary-foreground exist as well, because shadcn components expect them. They point at foreground or emphasis-foreground.

Tokens that are not classes

A few variables in themes.css do their work behind the scenes:

Variable What it does
--surface-accent A lighter hover fill. Any element with bg-card or bg-popover switches accent to this value, so hover:bg-accent shows up on a white card as well as on the page
--shadow-color The tint of the two shadows, shadow-md for popups and shadow-lg for floating panels. It is an RGB triple so the shadows can use it at different strengths
--chart-map The fill of countries without data on the dashboard maps

The rule behind --surface-accent, from themes.css:

.bg-card,
.bg-popover {
	--accent: var(--surface-accent);
}

Changing a token

Edit the value in themes.css. Change both the :root value and the .dark value, and check both modes:

:root {
	--background: #f4f6fa;
}

.dark {
	--background: #15191f;
}

The change reaches every page, because every component reads the token instead of a fixed color.

To change primary or destructive, edit src/styles/index.css. Colors shows how.

Adding a token

Add the variable to both blocks in themes.css, then map it in the @theme inline block in index.css:

/* themes.css */
:root {
	--highlight: #fff6d6;
}

.dark {
	--highlight: #3a3420;
}

/* index.css, inside @theme inline */
--color-highlight: var(--highlight);

bg-highlight, text-highlight and border-highlight now work and switch with the color mode. Add a token only when several parts of the interface share the color. For a single element, a palette class with a dark: variant does the job: bg-amber-50 dark:bg-amber-950.
