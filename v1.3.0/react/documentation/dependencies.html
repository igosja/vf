Dependencies

This page lists every package in package.json, what it does, and where the template uses it. Use it to decide what you can remove and to plan updates.

Updating packages

See which packages have newer versions:

npm outdated

The Wanted column shows the newest version that package.json allows. The ^ in front of each version allows minor and patch updates, which should not break anything. Install them with:

npm update

The Latest column can show a new major version, such as React Router 9 after 8. A major version can change how the package works. Read the package’s upgrade guide, install it on its own, and test the pages that use it:

npm install react-router@latest
npm run build
npm run dev

Update one major version at a time, so you know which package caused a problem.

After any update, run npm run build and click through the pages that use the package, using the “Used in” column above.

shadcn/ui components

The files in src/components/ui are copies of shadcn/ui components that the template has restyled. They are not an npm package, so npm update does not touch them. This is how shadcn/ui works: the code belongs to you.

To add a component the template does not include, use the shadcn command line tool. components.json already points it at the right folders:

npx shadcn@latest add hover-card

Do not run add for a component that already exists in src/components/ui. The tool would replace the restyled file with the plain shadcn version and undo the Materia design. Components Overview explains the changes the template made.

Removing packages

To remove a feature and its package, delete the files that use it first, then uninstall the package. Removing the Calendar app looks like this:

npm uninstall @fullcalendar/core @fullcalendar/react @fullcalendar/daygrid @fullcalendar/timegrid

Removing Features lists the files to delete for each feature.
