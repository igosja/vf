Overlays

Overlays open on top of the page: dialogs, side sheets, menus, popovers, tooltips and toasts. They all come from shadcn/ui and run on Radix UI, which handles focus, the keyboard and screen readers. Click the buttons in the previews to open them.

Each overlay has a trigger and content. Wrap your own button in the trigger with asChild, so the trigger takes your button’s look:

<DialogTrigger asChild>
	<Button variant="outline">Redeem code</Button>
</DialogTrigger>

Dialog

A dialog opens in the middle of the screen and dims the page behind it. Use it for a short task that needs the visitor’s full attention: confirm a deletion, fill in a small form. Its demo page is at /components/dialog.

import { Ticket } from "lucide-react";

import { DialogFoot, DialogHead, DismissButton } from "@/components/common/dialog-parts";
import { Button } from "@/components/ui/button";
import { Dialog, DialogClose, DialogContent, DialogDescription, DialogTrigger } from "@/components/ui/dialog";
import { Field, FieldLabel } from "@/components/ui/field";
import { InputGroup, InputGroupAddon, InputGroupInput } from "@/components/ui/input-group";

export default function RedeemDialog() {
	return (
		<Dialog>
			<DialogTrigger asChild>
				<Button variant="outline">Redeem code</Button>
			</DialogTrigger>
			<DialogContent showCloseButton={false} className="gap-0 p-0 sm:max-w-sm">
				<DialogHead>Redeem Code</DialogHead>

				<div className="px-6">
					<DialogDescription className="mb-5 text-sm text-muted-foreground">
						Enter a promo or gift code. Its value is added to your account credit and applied to your next invoice.
					</DialogDescription>

					<Field>
						<FieldLabel htmlFor="redeem-code">Code</FieldLabel>
						<InputGroup>
							<InputGroupAddon>
								<Ticket />
							</InputGroupAddon>
							<InputGroupInput id="redeem-code" className="uppercase placeholder:normal-case" placeholder="e.g. SAVE20" autoComplete="off" />
						</InputGroup>
					</Field>
				</div>

				<DialogFoot>
					<DismissButton />
					<DialogClose asChild>
						<Button>Redeem</Button>
					</DialogClose>
				</DialogFoot>
			</DialogContent>
		</Dialog>
	);
}

The template’s dialogs use three small helpers from src/components/common/dialog-parts.tsx, so every dialog lines up the same way:

Helper What it is
DialogHead The title row, with a close button on the right
DialogFoot The row of buttons at the bottom, aligned right
DismissButton A quiet Cancel button that closes the dialog

Pass showCloseButton={false} to DialogContent when you use DialogHead, because the head brings its own close button.

Opening a dialog from code

Without a trigger, control the dialog with open and onOpenChange:

const [open, setOpen] = useState(false);

<Dialog open={open} onOpenChange={setOpen}>
	<DialogContent>...</DialogContent>
</Dialog>;

// later, for example after a request finishes
setOpen(true);

Every dialog needs a DialogTitle, which DialogHead provides. Screen readers announce it when the dialog opens. If a dialog has no visible title, add one with className="sr-only".

Sheet

A sheet slides in from an edge of the screen. Use it for longer content that should keep the page in view, such as a filter panel or a details view. side picks the edge: right (the default), left, top or bottom. Its demo page is at /components/sheet.

import { Button } from "@/components/ui/button";
import { Field, FieldGroup, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
import { Sheet, SheetClose, SheetContent, SheetDescription, SheetFooter, SheetHeader, SheetTitle, SheetTrigger } from "@/components/ui/sheet";

export default function EditProfileSheet() {
	return (
		<Sheet>
			<SheetTrigger asChild>
				<Button variant="outline">Edit profile</Button>
			</SheetTrigger>
			<SheetContent>
				<SheetHeader>
					<SheetTitle>Edit profile</SheetTitle>
					<SheetDescription>Make changes to your profile here. Click save when you are done.</SheetDescription>
				</SheetHeader>
				<FieldGroup className="px-4">
					<Field>
						<FieldLabel htmlFor="sheet-name">Name</FieldLabel>
						<Input id="sheet-name" defaultValue="Pedro Duarte" />
					</Field>
				</FieldGroup>
				<SheetFooter>
					<SheetClose asChild>
						<Button>Save changes</Button>
					</SheetClose>
				</SheetFooter>
			</SheetContent>
		</Sheet>
	);
}

The sidebar drawer, the secondary sidebar drawer and the nav bar panels all use Sheet.

Dropdown menu

A dropdown menu lists actions under a button. Its demo page at /components/dropdown-menu also shows checkbox items, radio items and sub-menus.

import { CreditCard, LogOut, Settings, User } from "lucide-react";

import { Button } from "@/components/ui/button";
import {
	DropdownMenu,
	DropdownMenuContent,
	DropdownMenuGroup,
	DropdownMenuItem,
	DropdownMenuLabel,
	DropdownMenuSeparator,
	DropdownMenuShortcut,
	DropdownMenuTrigger,
} from "@/components/ui/dropdown-menu";

export default function AccountMenu() {
	return (
		<DropdownMenu>
			<DropdownMenuTrigger asChild>
				<Button variant="outline">Open menu</Button>
			</DropdownMenuTrigger>
			<DropdownMenuContent align="start" className="w-56">
				<DropdownMenuLabel>My Account</DropdownMenuLabel>
				<DropdownMenuGroup>
					<DropdownMenuItem>
						<User />
						Profile
						<DropdownMenuShortcut>⇧⌘P</DropdownMenuShortcut>
					</DropdownMenuItem>
					<DropdownMenuItem>
						<CreditCard />
						Billing
					</DropdownMenuItem>
					<DropdownMenuItem>
						<Settings />
						Settings
					</DropdownMenuItem>
				</DropdownMenuGroup>
				<DropdownMenuSeparator />
				<DropdownMenuItem variant="destructive">
					<LogOut />
					Log out
				</DropdownMenuItem>
			</DropdownMenuContent>
		</DropdownMenu>
	);
}

variant="destructive" colors an item red. DropdownMenuShortcut shows a keyboard shortcut on the right, as a hint only: wiring up the keys is up to you.

To make a menu item go to another page, use asChild with a React Router Link:

<DropdownMenuItem asChild>
	<Link to="/user/profile">Profile</Link>
</DropdownMenuItem>

Popover and tooltip

A popover opens a small panel next to its trigger and can hold anything, including form fields. The date pickers use one. A tooltip shows a short label when the pointer rests on its trigger or the trigger gets keyboard focus.

import { Info } from "lucide-react";

import { IconButton } from "@/components/common/icon-button";
import { Button } from "@/components/ui/button";
import { Field, FieldGroup, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
import { Popover, PopoverContent, PopoverTrigger } from "@/components/ui/popover";
import { Tooltip, TooltipContent, TooltipProvider, TooltipTrigger } from "@/components/ui/tooltip";

export default function PopoverAndTooltip() {
	return (
		<TooltipProvider>
			<div className="flex items-center gap-4">
				<Popover>
					<PopoverTrigger asChild>
						<Button variant="outline">Set dimensions</Button>
					</PopoverTrigger>
					<PopoverContent align="start" className="w-64">
						<FieldGroup className="gap-3">
							<Field>
								<FieldLabel htmlFor="width">Width</FieldLabel>
								<Input id="width" defaultValue="100%" />
							</Field>
							<Field>
								<FieldLabel htmlFor="height">Height</FieldLabel>
								<Input id="height" defaultValue="25px" />
							</Field>
						</FieldGroup>
					</PopoverContent>
				</Popover>

				<Tooltip>
					<TooltipTrigger asChild>
						<IconButton>
							<Info />
							<span className="sr-only">Information</span>
						</IconButton>
					</TooltipTrigger>
					<TooltipContent>Shows details about this card</TooltipContent>
				</Tooltip>
			</div>
		</TooltipProvider>
	);
}

Tooltips need a TooltipProvider above them. AppShell already wraps every page in one, so on your own pages a Tooltip works as it is. Keep tooltip text to a few words, and do not put a link or a button inside a tooltip, because the visitor cannot reach it.

Toasts

A toast is a short message at the bottom of the screen that goes away on its own. Call toast() from anywhere:

import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import { Toaster } from "@/components/ui/sonner";
import { ThemeProvider } from "@/providers/theme-provider";

export default function Toasts() {
	return (
		<ThemeProvider>
			<div className="flex flex-wrap gap-2">
				<Button variant="outline" onClick={() => toast("Event has been created")}>
					Default
				</Button>
				<Button variant="outline" onClick={() => toast.success("Settings saved")}>
					Success
				</Button>
				<Button variant="outline" onClick={() => toast.error("Could not save your settings")}>
					Error
				</Button>
				<Button variant="outline" onClick={() => toast("Message archived", { action: { label: "Undo", onClick: () => {} } })}>
					With action
				</Button>
			</div>
			<Toaster />
		</ThemeProvider>
	);
}

AppShell already renders the Toaster, so pages call toast() and never render a Toaster themselves. The preview above renders its own only because it runs outside the app. Forms shows toasts after a form submits.

Command

Command from src/components/ui/command.tsx is a searchable list. The template uses it inside a popover for the Combobox, at /components/combobox: a select that the visitor can type into to filter a long list.
