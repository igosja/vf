Deployment

Materia builds into a folder of static files: one index.html, plus JavaScript, CSS and images. Any web host that serves static files can run it. You do not need a Node.js server in production.

Build the site

Run the build in the app folder:

npm run build

The command checks the TypeScript types first. If it finds an error, it stops and prints the file and line. Fix the error and run the build again.

When it succeeds, the site sits in dist/:

dist/
├── index.html
├── assets/        JavaScript and CSS split into small files, with a hash in each name
└── img/           A copy of public/img

The hash in each file name changes whenever the file’s content changes. You can tell your host to cache everything in assets/ for a year, and visitors still get the new version after each deploy.

Test the build on your own computer before you upload it:

npm run preview

This serves dist/ at http://localhost:4173. Click through a few pages, then reload the browser on a page other than the dashboard to check that it still loads.

Send every address to index.html

Materia is a single-page app. The browser downloads index.html once, and React Router changes the page from then on. That works until a visitor reloads the browser on /apps/mail or opens a bookmark to it. The browser then asks the server for /apps/mail, and there is no such file on the server.

The fix is a rewrite rule: the server answers every address with index.html, and React Router reads the address and shows the right page. Each host sets this up in its own way.

Vercel

The template already includes the rule in vercel.json:

{
	"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}

Import the project on vercel.com, and Vercel detects Vite and builds it with no further settings.

Netlify

Create public/_redirects with this line:

/*  /index.html  200

Vite copies it into dist/, and Netlify reads it from there. Set the build command to npm run build and the publish directory to dist.

Cloudflare Pages

Cloudflare Pages serves index.html for any address that does not match a file, as long as the build has no 404.html. Materia’s build has none, so it works with no extra file. Set the build command to npm run build and the output directory to dist.

Apache

Create public/.htaccess:

<IfModule mod_rewrite.c>
	RewriteEngine On
	RewriteBase /
	RewriteRule ^index\.html$ - [L]
	RewriteCond %{REQUEST_FILENAME} !-f
	RewriteCond %{REQUEST_FILENAME} !-d
	RewriteRule . /index.html [L]
</IfModule>

The two RewriteCond lines leave real files, such as the JavaScript and images, alone. Your host needs mod_rewrite turned on, which most shared hosts have.

Nginx

Add try_files to the location block of your site:

location / {
	root /var/www/materia/dist;
	try_files $uri $uri/ /index.html;
}

Other hosts

Look in your host’s documentation for “single-page app”, “SPA fallback” or “rewrite to index.html”. If the host cannot rewrite addresses, the site still loads from its home page, but reloading any other page shows the host’s 404 page.

Deploy to a sub-folder

The template expects to live at the root of a domain, such as https://admin.example.com/. A sub-domain is the simplest setup. To serve it from a folder instead, such as https://example.com/admin/, change three things.

1. Tell Vite the folder. In vite.config.ts, add base:

export default defineConfig({
	base: "/admin/",
	plugins: [react(), tailwindcss()],
	// ...
});

Vite then adjusts the paths in index.html, the CSS url() references and the imported files.

2. Tell React Router the folder. In src/main.tsx, pass basename:

const router = createBrowserRouter(routes, { basename: "/admin" });

3. Fix the image paths in the code. Pages refer to images in public/img with paths that start at the root, such as "/img/contacts/2.jpg". Vite does not rewrite paths written inside your code. Prefix them with import.meta.env.BASE_URL, which Vite fills in with the base you set:

<img src={`${import.meta.env.BASE_URL}img/contacts/2.jpg`} alt="" />

Search src/ for "/img/ to find each one. About two dozen files in src/pages, src/data and src/components use them.

Then update your host’s rewrite rule to point at /admin/index.html.

Environment variables

Vite reads .env files in the app folder. Only variables that start with VITE_ reach your code:

# .env.production
VITE_API_URL=https://api.example.com

const response = await fetch(`${import.meta.env.VITE_API_URL}/orders`);

Vite writes these values into the JavaScript at build time, so anyone who opens your site can read them. Never put a secret key in a VITE_ variable. The template’s .gitignore keeps .env files out of Git, except .env.example.

Checklist before you go live

  1. npm run build finishes with no errors.
  2. npm run preview works, including a reload on a page other than the dashboard.
  3. The host has a rewrite rule that sends every address to index.html.
  4. You changed the page title in index.html and the favicon in public/img/favicon/. Branding lists everything that carries the template’s name.
  5. You removed the demo pages you do not need. Removing Features explains how.
