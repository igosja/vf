Forms

Materia builds forms from shadcn/ui’s form components, restyled to its design. Validation runs on React Hook Form with a Zod schema.

The template has five form pages to copy from:

Page Address What it shows
Form Elements /forms/elements Every input, select, checkbox, radio, switch and slider
Input Groups /forms/input-groups Icons, text and buttons inside a field, and joined button groups
Form Layouts /forms/layouts Forms in one and two columns, with fieldsets
Form Templates /forms/templates Complete forms: sign-up, payment, shipping, profile
Form Validation /forms/validation Five working forms with React Hook Form and Zod

Fields

Field from src/components/ui/field.tsx wraps one input with its label, its help text and its error. FieldGroup stacks fields with even spacing.

import { Field, FieldDescription, FieldError, FieldGroup, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
import { NativeSelect, NativeSelectOption } from "@/components/ui/native-select";
import { Textarea } from "@/components/ui/textarea";

export default function FormFields() {
	return (
		<FieldGroup className="max-w-md">
			<Field>
				<FieldLabel htmlFor="name">Full name</FieldLabel>
				<Input id="name" placeholder="Evil Rabbit" />
				<FieldDescription>Shown on your profile and in emails.</FieldDescription>
			</Field>
			<Field data-invalid>
				<FieldLabel htmlFor="email">Email</FieldLabel>
				<Input id="email" type="email" defaultValue="rabbit@" aria-invalid />
				<FieldError>Enter a valid email address.</FieldError>
			</Field>
			<Field>
				<FieldLabel htmlFor="country">Country</FieldLabel>
				<NativeSelect id="country" defaultValue="ca">
					<NativeSelectOption value="us">United States</NativeSelectOption>
					<NativeSelectOption value="ca">Canada</NativeSelectOption>
					<NativeSelectOption value="uk">United Kingdom</NativeSelectOption>
				</NativeSelect>
			</Field>
			<Field>
				<FieldLabel htmlFor="bio">Bio</FieldLabel>
				<Textarea id="bio" placeholder="Tell us a little about yourself" />
			</Field>
		</FieldGroup>
	);
}
Component What it is
FieldGroup A column of fields with even gaps
Field One field. orientation="horizontal" puts the control beside its label
FieldLabel The label. Point htmlFor at the input’s id
FieldDescription Help text under the input
FieldError The error message. Pass text as children, or React Hook Form errors through errors
FieldContent Groups a label and a description beside a checkbox or a switch
FieldTitle A bold line inside a choice card
FieldSet, FieldLegend A titled group of related fields
FieldSeparator A line between groups of fields, with optional text such as “Or”

To show a field as invalid, set data-invalid on the Field and aria-invalid on the input. The label turns red, the input gets a red border, and screen readers announce the field as invalid.

Checkboxes, radios, switches and sliders

import { Checkbox } from "@/components/ui/checkbox";
import { Field, FieldContent, FieldDescription, FieldGroup, FieldLabel, FieldTitle } from "@/components/ui/field";
import { RadioGroup, RadioGroupItem } from "@/components/ui/radio-group";
import { Slider } from "@/components/ui/slider";
import { Switch } from "@/components/ui/switch";

export default function FormChoices() {
	return (
		<FieldGroup className="max-w-md">
			<Field orientation="horizontal">
				<Checkbox id="terms" defaultChecked />
				<FieldContent>
					<FieldLabel htmlFor="terms">Accept terms and conditions</FieldLabel>
					<FieldDescription>By clicking this checkbox, you agree to the terms and conditions.</FieldDescription>
				</FieldContent>
			</Field>

			<RadioGroup defaultValue="monthly">
				<Field orientation="horizontal">
					<RadioGroupItem value="monthly" id="monthly" />
					<FieldLabel htmlFor="monthly">Monthly billing</FieldLabel>
				</Field>
				<Field orientation="horizontal">
					<RadioGroupItem value="yearly" id="yearly" />
					<FieldLabel htmlFor="yearly">Yearly billing</FieldLabel>
				</Field>
			</RadioGroup>

			<FieldLabel htmlFor="notifications">
				<Field orientation="horizontal">
					<FieldContent>
						<FieldTitle>Email notifications</FieldTitle>
						<FieldDescription>Get an email when someone mentions you.</FieldDescription>
					</FieldContent>
					<Switch id="notifications" defaultChecked />
				</Field>
			</FieldLabel>

			<Field>
				<FieldLabel>Volume</FieldLabel>
				<Slider defaultValue={[60]} max={100} aria-label="Volume" />
			</Field>
		</FieldGroup>
	);
}
  • A checkbox or radio sits beside its label with orientation="horizontal".
  • Wrapping a whole Field in a FieldLabel turns it into a choice card: the full card is clickable and highlights when its control is checked. The switch above uses this pattern.
  • Slider takes its value as an array, [60], because it supports ranges with two thumbs: [20, 80].

Select and NativeSelect

The template has two dropdowns:

  • Select opens a styled list in a popover. Use it when the list should match the rest of the design.
  • NativeSelect is the browser’s own <select> with the template’s border and caret. On phones it opens the system picker, which is easier to use with a thumb.
<Select defaultValue="pro">
	<SelectTrigger className="w-full">
		<SelectValue placeholder="Choose a plan" />
	</SelectTrigger>
	<SelectContent>
		<SelectItem value="starter">Starter</SelectItem>
		<SelectItem value="pro">Pro</SelectItem>
		<SelectItem value="business">Business</SelectItem>
	</SelectContent>
</Select>

For a long list that people should search, use the Combobox pattern from the Combobox page at /components/combobox. It puts a Command list inside a Popover.

Input groups and button groups

InputGroup puts icons, text and buttons inside one field border. ButtonGroup joins separate inputs and buttons edge to edge.

import { Mail, Search } from "lucide-react";

import { Button } from "@/components/ui/button";
import { ButtonGroup } from "@/components/ui/button-group";
import { Input } from "@/components/ui/input";
import { InputGroup, InputGroupAddon, InputGroupButton, InputGroupInput, InputGroupText } from "@/components/ui/input-group";
import { Kbd } from "@/components/ui/kbd";

export default function FormInputGroup() {
	return (
		<div className="flex max-w-md flex-col gap-4">
			<InputGroup>
				<InputGroupInput placeholder="Search..." aria-label="Search" />
				<InputGroupAddon>
					<Search />
				</InputGroupAddon>
				<InputGroupAddon align="inline-end">
					<Kbd>⌘K</Kbd>
				</InputGroupAddon>
			</InputGroup>

			<InputGroup>
				<InputGroupAddon>
					<InputGroupText>https://</InputGroupText>
				</InputGroupAddon>
				<InputGroupInput placeholder="example.com" aria-label="Website" />
				<InputGroupAddon align="inline-end">
					<InputGroupButton>Check</InputGroupButton>
				</InputGroupAddon>
			</InputGroup>

			<ButtonGroup className="w-full">
				<Input placeholder="Enter your email" aria-label="Email" />
				<Button variant="outline">
					<Mail />
					Subscribe
				</Button>
			</ButtonGroup>
		</div>
	);
}

InputGroupAddon goes before the input by default. align="inline-end" moves it after the input, and align="block-start" or align="block-end" puts it above or below, which suits a text area with a toolbar.

Validation

The Form Validation page shows the full pattern. Here is the Bug Report form from src/pages/forms/validation/page.tsx.

1. Describe the data with a Zod schema. Each rule carries its own error message:

import { z } from "zod";

const bugReportSchema = z.object({
	title: z.string().min(5, "Bug title must be at least 5 characters.").max(32, "Bug title must be at most 32 characters."),
	description: z.string().min(20, "Description must be at least 20 characters.").max(100, "Description must be at most 100 characters."),
});

2. Create the form with useForm and connect the schema through zodResolver:

import { zodResolver } from "@hookform/resolvers/zod";
import { Controller, useForm } from "react-hook-form";

const form = useForm({
	resolver: zodResolver(bugReportSchema),
	defaultValues: { title: "", description: "" },
});

3. Render each field with a Controller. It hands the input its value and change handler in field, and the validation result in fieldState:

<form onSubmit={form.handleSubmit(showSubmitted)}>
	<FieldGroup>
		<Controller
			name="title"
			control={form.control}
			render={({ field, fieldState }) => (
				<Field data-invalid={fieldState.invalid}>
					<FieldLabel htmlFor="bug-title">Bug Title</FieldLabel>
					<Input {...field} id="bug-title" aria-invalid={fieldState.invalid} placeholder="Login button not working on mobile" autoComplete="off" />
					{fieldState.invalid && <FieldError errors={[fieldState.error]} />}
				</Field>
			)}
		/>
	</FieldGroup>
	<Button type="submit">Submit</Button>
</form>

form.handleSubmit runs the schema first. It calls your function only when every field passes, and passes it the values with their types. Until then, each field shows its own error.

The other forms on the page show more rules: matching passwords, a box the visitor must tick, a list of checkboxes with a minimum, and a list of emails the user can grow and shrink.

Sending the data

Replace the demo’s showSubmitted with your own function, and send the values to your server:

async function onSubmit(values: z.infer<typeof bugReportSchema>) {
	const response = await fetch("/api/bugs", {
		method: "POST",
		headers: { "Content-Type": "application/json" },
		body: JSON.stringify(values),
	});

	if (response.ok) toast.success("Bug report sent");
	else toast.error("Could not send the report. Try again.");
}

<form onSubmit={form.handleSubmit(onSubmit)}>...</form>

z.infer turns the schema into a TypeScript type, so values has the right field names and types with no extra work.

Toasts

Toasts are the small messages that slide up from the bottom of the screen, such as “Bug report sent”. They come from Sonner. AppShell already renders the Toaster, so any page can show one:

import { toast } from "sonner";

toast("Event has been created");
toast.success("Settings saved");
toast.error("Could not save your settings");
toast("Message archived", {
	action: { label: "Undo", onClick: () => restore() },
});

src/components/ui/sonner.tsx styles them as a dark pill in the center at the bottom, raised above the bottom nav bar on phones. Its demo page is at /components/sonner.
