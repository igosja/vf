Working with Data

Every number, name and row in the template comes from a file in src/data/. The pages import these files. This keeps the demo self-contained, and it gives each piece of data a TypeScript type that you can reuse when you connect your own server.

The data files

File What it holds
analytics.ts, crm.ts, e-commerce.ts, email-marketing.ts, project-management.ts, saas.ts The cards and charts of each dashboard
mail.ts, contacts.ts, messages.ts, channel.ts, file-manager.ts, photos.ts, todo-lists.ts, calendar.ts, ai-agent.ts The apps
user.ts, teams.ts The User pages and the Teams page
billing.ts, invoice.ts, pricing.ts, faq.ts, search.ts The other pages
notifications.ts The notifications panel in the nav bar
charts.ts, tables.ts The samples on the Charts and Tables pages
navigation.ts The sidebar menu

Each file exports types and constants. A page imports what it needs:

import { RECENT_ORDERS, type RecentOrder } from "@/data/e-commerce";

To change what the template shows, edit the values in the file. The page updates as soon as you save.

Loading data from your server

When your data comes from an API, fetch it and pass it to the page in the same shape as the data file. The types in src/data/ already describe that shape, so keep them and drop the demo constants.

With a route loader (recommended)

React Router can load a page’s data before it shows the page. Export a loader function from the page file:

import { useLoaderData } from "react-router";

import type { Order } from "@/data/orders";

export async function loader() {
	const response = await fetch(`${import.meta.env.VITE_API_URL}/orders`);
	if (!response.ok) throw new Response("Could not load orders", { status: response.status });
	return (await response.json()) as Order[];
}

export default function Orders() {
	const orders = useLoaderData<typeof loader>();

	return <OrdersTable orders={orders} />;
}

Then return the loader next to the component in src/routes.tsx:

{
	path: "orders",
	lazy: async () => {
		const { default: Component, loader } = await import("@/pages/orders/page");
		return { Component, loader };
	},
},

This gives you three things with no extra code:

  • Loading screen. While the loader runs, the template’s loading screen shows between pages, as it does while a page downloads.
  • No empty first render. The page renders once, with its data already there.
  • Errors. If the loader throws, React Router shows the closest error boundary. Pages and Routes shows how to add your own.

The React Router data loading guide covers loaders in full, including how to read the address’s parameters.

With useEffect

For data that loads after the page shows, such as a panel that refreshes, fetch in an effect:

const [orders, setOrders] = useState<Order[]>([]);
const [loading, setLoading] = useState(true);

useEffect(() => {
	let ignore = false;

	fetch(`${import.meta.env.VITE_API_URL}/orders`)
		.then((response) => response.json())
		.then((data: Order[]) => {
			if (!ignore) setOrders(data);
		})
		.finally(() => setLoading(false));

	return () => {
		ignore = true;
	};
}, []);

ignore stops an old request from overwriting newer data when the component unmounts first. While loading is true, show Skeleton placeholders in the shape of the content. Data Display shows them.

With a data library

For an app with many requests, caching and refetching, a library such as TanStack Query handles loading states, retries and caching for you. Install it, wrap the app in its provider in src/main.tsx, and call its hooks in your pages.

Where to keep the API address

Put the address of your API in an environment file in the app folder, so it can differ between your computer and production:

# .env.development
VITE_API_URL=http://localhost:3000/api

# .env.production
VITE_API_URL=https://api.example.com

Only variables that start with VITE_ reach your code, and they are visible to anyone who opens the site. Keep secret keys on your server. Deployment covers environment variables.

Sending data

Forms send their data from their submit handler. Forms shows a complete example with validation, a fetch call and a toast for the result.

Dates in the demo data

Some demo data builds its dates from today, so the calendar and the charts always show recent dates. The calendar events, for example, fall in the current month:

const month = (() => {
	const now = new Date();
	return `${now.getFullYear()}-${String(now.getMonth() + 1).padStart(2, "0")}`;
})();

Your real data has fixed dates, so you can drop helpers like this when you connect your server.
