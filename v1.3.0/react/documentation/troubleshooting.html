Troubleshooting

Answers to the problems that come up most often, grouped by when they happen.

Installing

npm install fails with an “engine” error

React Router 8 needs Node.js 22.22 or newer, and npm refuses to install it on an older version. Check your version with node -v, install a newer Node.js from nodejs.org, and run npm install again.

npm install prints warnings about install scripts

Recent npm versions list packages whose install scripts they skipped. The template does not need any of them, so you can ignore these warnings.

The install takes a long time or fails partway

Delete node_modules and try again:

rm -rf node_modules
npm install

On Windows, delete the node_modules folder in the file explorer instead of using rm.

Running the development server

The address in the browser shows nothing, or a different app

Another program may be using port 5173, and Vite has picked the next free port. Read the address Vite prints in the terminal, or choose a port yourself:

npm run dev -- --port 3000

A change does not show up

Vite updates the page as you save. If a change still does not show, check the terminal for an error, then reload the page. For a change to index.html or vite.config.ts, stop the server with Ctrl+C and start it again.

Styling

A Tailwind class has no effect

Tailwind finds the classes you use by reading your files as text, and it only generates the classes it finds written out in full. A class built from pieces never appears in full, so Tailwind never generates it:

// Tailwind cannot see "bg-emerald-500" here
<span className={`bg-${color}-500`} />

Write every class out in full, and choose between them in code:

const STATUS_CLASS = {
	active: "bg-emerald-500",
	failed: "bg-red-400",
};

<span className={STATUS_CLASS[status]} />;

This is why the template’s data files store complete class names, such as color: "text-cyan-500". The Tailwind docs on dynamic class names explain this.

A class I pass in className does not override the component

Components join your classes with theirs through cn(), which lets the later class win for the same property. If yours does not win, check that it targets the same property: p-4 overrides p-6, but pt-4 only overrides the top. Classes that the component applies in a variant, such as a button’s colors, also give way to yours.

The page flashes light colors before turning dark

The script in index.html sets the color mode before the page paints. If you edited index.html and moved or removed that script, put it back in the <head>. Light and Dark Mode shows it.

Charts and maps

A chart is empty

Check two things:

  1. The container has a height. With maintainAspectRatio: false, the chart takes its height from its container. Give the container a class such as h-66.
  2. The chart type is registered. The browser console then shows an error that something “is not a registered controller”, “element” or “scale”. Register the missing part in src/components/charts/use-chart-theme.ts. Charts shows how.

A chart color shows as black or does not change

Chart colors must come from CHART_COLORS, paletteColor() or alpha(). Chart.js cannot read Tailwind classes or var(--color-…) strings. Chart Colors explains why.

A map redraws all the time

VectorMap redraws whenever it receives a new options object. Move the options into a constant outside your component. Maps shows the pattern.

TypeScript

npm run build stops with a TypeScript error

The build checks the types first. The error message names the file, the line and the problem. The most common ones in a fresh change:

Message Fix
'X' is declared but its value is never read Delete the unused import or variable
Cannot find module '@/…' Check the path. @/ points at src/
Property 'x' does not exist on type The data does not match its type. Add the field to the type in src/data/, or fix the name
'X' is a type and must be imported using a type-only import Write import type { X } or import { type X }

Run npm run typecheck to see every error at once.

Deployment

Reloading a page on the live site shows a 404 page

The server needs a rule that sends every address to index.html. Deployment has the rule for each common host.

Images or styles are missing on the live site

If the site lives in a folder, such as example.com/admin/, Vite and React Router need to know the folder, and the image paths in the code need a prefix. Deployment lists the three changes.

The live site shows an old version

Each build gives its JavaScript and CSS files new names, so browsers fetch the new versions. index.html itself keeps its name, so tell your host not to cache it, or to cache it for a short time. Most static hosts already do this.

Questions about the template

How do I change the home page?

The route with index: true in src/routes.tsx is the home page. It shows the E-Commerce dashboard. Point its import() at another page to change it, and update the to: "/" link in src/data/navigation.ts to match.

Does the template include a backend or a login system?

No. Materia is the front end of an app. The Login and Register pages are the screens only: Login moves to the dashboard and Register does the same, with no account behind them. Connect them to your own authentication, such as your server’s API or a service like Auth0 or Clerk.

Can I use Next.js instead of Vite?

The components work in any React setup, but the routing and the frame use React Router. Moving to Next.js means replacing src/routes.tsx and the layout routes with Next.js’s own app router.

How do I update the template to a new version?

The template is your code once you start changing it, so there is nothing to install. Compare the new version’s files with yours and copy over the changes you want. A diff tool such as the one in Visual Studio Code or Git makes this quick. Start with package.json to pick up package updates, then the components you have not changed.
